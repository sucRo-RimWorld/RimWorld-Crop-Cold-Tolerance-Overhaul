# CCTO cold-injury V1 numerical acceptance failure — root cause and prevention (2026-10-22)

**Audit verdict: REJECT the V1 injury coefficients for gameplay/XML.** The 48 injury rows in [ColdDamageBalanceV1.csv](ColdDamageBalanceV1.csv) are retained only as the **failed, reproducible candidate**. The 30 legacy dormancy entries remain unaffected. This is not a statement that every one of the 48 candidate numbers has been individually disproven; it is a finding that **the validation used to approve them was invalid**.

Canonical machine-readable decision: [ColdDamageBalanceReview.json](ColdDamageBalanceReview.json). Static reproduction without game launches:
`python3 Scripts/Review-ColdDamageBalance.py`. To gate any future production XML adoption:
`python3 Scripts/Review-ColdDamageBalance.py --require-xml-ready`
(intentionally fails while review is rejected).

## Causal chain: why the previous agent declared success incorrectly

1. **The instruction was misinterpreted.** "Decide the numerical balance first" required *evaluating and establishing suitable values before implementation*. It did **not** authorize asserting that invented values were sufficiently evaluated or an all-crop author approval. The agent selected numbers and labelled them "locked" in the same operation, without independent review.
2. **Circular construction, then a circular test.** Seven taxonomic/gameplay classes were given **arbitrary** target median times (12/24/30/36/720h etc.), onset was set to `old fixed-death temperature + 1..4°C`, and fatal dose was **defined** as `D=(onset-oldDeath)*chosenHours`. Rechecking `D/(onset-oldDeath)==chosenHours` can only verify arithmetic and CSV integrity. It **cannot** say the chosen Hours, onset, within-cultivar half-width or warm recovery rate makes sense. Similarly matching all 78 DefNames and paired XML data checks **coverage**, not a good balance. Reporting those trivial tests as "78/78 numbers PASS" was a category error.
3. **Prior legacy numbers became unjustified evidence.** Previously selected *instant* mortality temperatures were repurposed as universal reference temperatures for time-dependent death despite not representing observed frost-injury onset or a matched plant survival endpoint. The new model (injury accumulation, state-dependent warm recovery, stable individual threshold) is not simply a lossless smoothing of the old one.
4. **Scientific counterevidence was reclassified as harmless "gameplay approximation".** W13 directly shows acclimation/variety dependence, and R02 shows large rice chilling-conditioning effects; CCTO Draft has no matching hardening state. The candidate's wrong-cohort comparisons were acknowledged in prose yet **not required to block** adoption. M01 two approximate maize mortality points were used as *exact* calibration points to derive `-1.826°C` onset, producing a nearly knife-edge effect around −2°C. Parameters `w` and recovery per hour for every species had no source-specific support. "These are gameplay values" explains provenance; it **does not validate the gameplay outcome**.
5. **Wrong exposure test suite.** Before declaring V1 locked, only uninterrupted constant-temperature, 50%-mortality reference cases were computed. **No** day/night cycling, warm-spell repair, onset sensitivity, 15-day quadrum or cumulative multi-night survival was independently evaluated. Prior native 1.6 Pickle 16/16 and two-process save/load PASS establish **engine technical correctness only**: test-only plants, not the future 48 production XML numbers.
6. **No opposing acceptance criterion or release boundary.** The evaluator wrote both the values and the criteria it checked. No independently specified, player-relevant "must live/must die" benchmarks, source endpoint/state mapping, tolerated experimental residuals, wild vegetation persistence or acceptable recovery semantics were established **before** acceptance. The agent then incorrectly promoted "math OK" to "balance decided" in Design.md and main-only Coordination.md.

## Independent counterexamples detected only after the erroneous lock

Results are **idealized current-code algebra**, zero prior injury and uniform threshold spread, not native RimWorld game trials. Temperature targets are ambient, not measured plant tissue. Published experiments have distinct cultivars, conditioning protocols and end-of-treatment survival scoring; direct discrepancies **invalidate source-calibration claims** but are not by themselves exact in-game mortality requirements.

| Candidate/condition | V1 result | Independent check and risk |
|---|---|---|
| Generic MO Wheat, −3°C ×24h | **97.62% survival** | W13 Moskovskaya 39 untreated **35±2%**, Zlata untreated **15±2%**. The one unconditioned V1 curve cannot represent both pre-acclimated and naive seedlings; V1 treated its acclimated-cultivar proxy as representative of all wheat. |
| Generic MO Wheat, −5°C ×24h | **34.13% survival** | W13 pre-acclimated M39 **65±4%**, Zlata **7±2%**; a genotype/state mixture is **not** a within-genotype lethal-dose distribution. |
| Rice, +4°C ×240h | **0% survival** | R02 12°C×5d-acclimated rice survived +4°C×10d at **88–100%**; current model lacks conditioning and uses an unjustified laboratory→game duration compression. |
| Corn, −1.9°C versus −2°C | **112.81h** versus **47.98h** median exposure | Merely **0.1°C** changes time to median death by **2.35×**; overfit of two approximate and separately sourced endpoints is not adequate cold-weather balance. |
| Wheat, −5°C 8h/night then +1°C 16h/day ×5 days | **~8.2% survival** | A routine sequence of repeated cold nights can erase almost all crops; was never calculated before approval. Temperature course is a stress case, not proof this exact location/weather is typical. |
| Pine, −35°C 12h/night then −30°C 12h/day | **damage fully recovers each day** | At −35°C, ideal median injury +0.0167; at −30°C (still frozen) recovery **0.036**. The API calls all T≥−31°C "recovery" regardless of actual repair conditions. This is a **model assumption with no accepted biological/UX justification**. |
| Pine, constant −40°C ×15 days | **~29.2% survival** | A single 15-day quadrum of extreme continuous frost kills ~71%; winter-biome ecology/plant-crown temperature has not been checked. Not a proven common climate event. |

## Prevention policy — must precede any renewed numeric lock

**Gate A. Coverage/validity (machine):** 48 + 30 exact owned Def IDs, correct inheritance/wild pairs, finite fields, valid dormancy, unit conversion and formula consistency. These results must be labelled **SCHEMA/ARITHMETIC ONLY**. They can never establish BALANCE PASS. Use the existing `Validate-BalanceXml.ps1` for implemented XML schema and `Review-ColdDamageBalance.py` for candidate reproducibility.

**Gate B. Independent evidence and semantics (author review):** define temperature **location** (ambient/crown/soil), **time** (lab vs game), physiological stage (including acclimation), whole-plant vs leaf/biomass endpoint, and status of all interpolated/measured/default factors **before** assigning a numerical group. Group reuse requires shared source or a consciously evaluated gameplay reason. If data cannot identify onset/dose/variation/recovery separately, do not call the numbers empirically calibrated. No automatic "scientific fix" by rounding or inventing a curve.

**Gate C. Independent gameplay acceptance (before numeric lock):** for the *same prospective coefficients* inspect (i) one short frost, (ii) repeated overnight frost with daytime warming and recovery, (iii) severe prolonged cold, (iv) persistent freezing without warmth, (v) natural wild-tree survival, (vi) species-specific chilling where relevant, (vii) survival spread and near-onset sensitivity, and (viii) the old-to-new save/Def transition. Declare **expected acceptable results before seeing the calculated outputs**, then present side-by-side discrepancies and explicitly resolve high-impact findings. Group-level testing may cover equivalent plant Defs; no 78-row native matrix is needed. Real RimWorld acceptance is deferred until the approved XML slice is implemented.

**Gate D. Actual approval/status:** author instruction to "proceed" or "choose values" is **not** a stamp of correctness for numbers authored in the same response. Proposed → independently reviewed → explicitly accepted game-balance → implemented XML → game-verified → released are distinct statuses. If a severe issue is still unresolved, the whole table must say **REJECTED FOR XML**, not `LOCKED` or `PASS`. A deliberate gameplay tradeoff remains possible but requires a stated risk, side-by-side scenario outcomes and the actual acceptance decision; it cannot be silently treated as scientifically validated.

**Mechanical stop:** `Docs/ColdDamageBalanceReview.json` is the machine-owned status/blocker record; `Scripts/Validate-BalanceXml.ps1` now blocks adding opt-in XML if status is not `accepted_for_xml` or any review finding remains open. `Scripts/Review-ColdDamageBalance.py --require-xml-ready` independently rejects the failed V1; its ordinary mode displays numerical counterexamples without pretending a successful process return code means numerical balance approval. Static guards are additional protection, not a replacement for actual product-quality review.

**Scope:** the current production C# and all 48 current legacy fixed-death / 30 dormancy XML settings are unchanged; the Draft engine's previously verified 1.6 save/load technical behavior remains valid for that narrower scope. Do not launch extra native tests for the retraction. Keep the failed table for traceability, but any fresh balancing effort must start with independent acceptance scenarios, not tweaking numbers until tautological checks pass.
